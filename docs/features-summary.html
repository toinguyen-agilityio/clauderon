Clauderon · feature summary

What Clauderon does today

One line per feature, grouped by what a Member does. Generated from the repo's features file, so the page and the code agree.

The core idea

A Member picks Tickets, runs them through a Flow of Nodes, and each Run executes on that Member's own Machine under their own logins.

Tickets 8

Pick GitHub issues as the work to do.

  • DoneTicket list Tickets per Project with key, title, labels and Ticket Status.
  • DoneSearch and filter Tickets Search by title or key; filter by Project and Ticket Status.
  • DoneSelect Tickets and Start Select several Tickets and Start Runs from the list.
  • DoneSync Pulls open issues and the current state of known Tickets and Run pull requests from GitHub; never starts a Run.
  • DoneTicket Status Derived, never stored: Open, Queued, In run, Needs you, Failed, Interrupted, PR open, PR merged, Closed.
  • DoneOne Active Run per Ticket A Ticket has at most one Active Run; Dry-runs do not count.
  • DoneNo writes to issues The app never changes issue state or labels or comments; pull requests say Refs #n.
  • DoneAuthor association warning Sync records the author's association; Start warns when it is not owner, member or collaborator.

Flows and Nodes 11

Build the process from typed Nodes.

  • DoneNode library Nodes (Agent, Command, Human, Ticket) with typed inputs and Outputs, listed and edited on the library page.
  • DoneCanvas editor Drag Nodes from the library onto a Flow and connect Outputs to inputs.
  • DoneTyped edges An edge is allowed only when the Output Type matches the input; a mismatch shows an error.
  • DoneFlow validation One Ticket Node, an end Node, no cycles, no unconnected required input; problems block Runs.
  • DoneNode panel Per-Flow name, extra instructions and optional Outputs for a placed Node.
  • DoneFlow edit lock A Flow cannot be edited or deleted while an Active Run uses it; it can be viewed and cloned.
  • DoneSeeded sample Nodes and Flows Sample Nodes and Flows are seeded and only added when missing; they can be cloned and edited.
  • DoneCreate and edit Flows Any Member creates, edits and deletes Flows and library Nodes; every change is audited.
  • DoneLibrary Node lock A library Node cannot be edited while a Flow using it is locked; edits change every Flow that uses it.
  • DoneFlow drafts from Claude Describe a Flow in words and Claude drafts it on the Member's Machine outside a Run; review it before it becomes a Flow.
  • DoneImport and export Flows and Nodes Flows and library Nodes can be exported to and imported from files.

Runs 10

Run a Flow for a Ticket, one Node at a time.

  • DoneStart dialog and Batches Pick a Flow, Tickets, extra instructions and mode Real or Dry-run; one Run per Ticket, Runs started together form a Batch.
  • DoneRun engine The Gateway runs a Flow's Nodes one at a time in topological order and keeps all Run state in the database.
  • DoneWorktree and branch per Run Each Run gets a worktree and branch clauderon/<issue>-<slug>-<run id> on the Starter's Machine.
  • DoneCancel a Run Cancel ends any Active Run as Cancelled.
  • DoneFailed Runs stay Active A Failed or Interrupted Run keeps the Ticket's Active Run and the Flow lock, but not a Slot, until retried or cancelled.
  • DoneReal runner Agent Nodes run claude -p and Command Nodes run shell on the Starter's Machine; logs stream to the browser; the structured result is checked against Output Types.
  • DoneOpen a pull request Node Pushes the branch and opens or updates the pull request with the Starter's gh login; no changes means no pull request.
  • DoneHeartbeat, resume and Interrupted Runs 10 s heartbeat over one WebSocket with message ids; under 30 s resumes, longer marks Running Runs Interrupted and orphans are killed.
  • DoneWorktree cleanup The worktree is deleted when a Run Succeeds or is Cancelled, and kept while Failed or Interrupted.
  • DoneRun success rule A Run succeeds when every Node it reaches succeeds; a missing optional Output does not fail it.

People in the loop (Approve, Grill) 6

A Run pauses for a person to decide or answer.

  • DoneHuman Nodes: Approve and Grill Approve or Reject with feedback; Grill rounds of questions answered in one form, resuming the same Claude session.
  • DoneWaiting for human A Human Node puts the Run in waiting for human; it keeps its Slot and has no timeout.
  • DoneNeeds you queue One page lists every Node waiting for a person, across all Runs.
  • DoneReject fails the Run Rejecting an Approve Node fails the Node and the Run, keeping the feedback.
  • DoneRetry from any Node Retry a Failed or Interrupted Run from any Node as new Attempts, with review feedback, failure context and a note.
  • DoneAny Member responds to any Run Any Member can approve, reject, answer, cancel and retry any Run; Start and the terminal use the Member's own Machine.

Tracking results 5

See what a Run did and which pull requests it opened.

  • DoneRun page Timeline of Nodes with state, duration and live log; logs are kept after the Run ends.
  • DoneOutputs per Attempt Each Node's Outputs are shown per Attempt on the Run page.
  • DoneUsage Tokens and duration per Node and totals per Run, as reported by Claude Code; no money cost.
  • DoneRuns list Runs with Ticket, Flow, mode, state, Starter and times; filter by state, Flow and Machine.
  • DonePull requests page Lists the pull requests opened by Runs; replaces the dropped Diff, Artifact and Batch page.

Machines and the Agent 12

Each Member runs Runs on their own computer.

  • DoneAgent connects out to the Gateway The Agent on each Machine connects out over one WebSocket (no inbound ports) and runs as a user service.
  • DonePairing a Machine A Member pairs their computer with a one-line install; a code approved on the Machines page issues a token stored only as a SHA-256 hash.
  • DoneAgent self-update and Doctor The Agent is one esbuild bundle with its own Node that updates itself from the web app; Doctor checks the Machine and reports to its page.
  • DoneRuns on the Starter's Machine, Slots and queue Each Run executes on its Starter's Machine; Running Runs never exceed the Machine's Slots, extra Runs queue first-in, first-out.
  • DoneMachines page Machine cards with connection, hardware, logins, Slots in use and queue; one page per Machine.
  • DoneMachine Ready and login checks Start is refused until the Machine's Claude Code and gh logins are present; the Agent only checks status and Doctor reports problems.
  • DoneWorkspace with a worktree per Run Per Machine, one clone per Project and one git worktree per Run under ~/.clauderon.
  • DonePush with the Starter's own gh login Pushes and pull requests use the Starter's gh login on their Machine; the app holds no write token.
  • DoneAgent permissions skipped Claude Code runs headless in Agent and Grill Nodes with permission prompts skipped, under the Member's own login.
  • DoneNo outbound network limit v1 does not restrict a Machine's outbound network; an accepted risk.
  • DoneResilience The Agent reconnects by itself after a network drop or restart and resumes from message ids.
  • DoneIsolation Each Member's Runs run on their own Machine under their own logins, so one Member's Workspace is not another's.

Sign-in and team 8

Who gets in, which Projects are enabled, and what is recorded.

  • DoneGoogle sign-in Members sign in with Google; only allowlisted emails get in, others see an access-denied page.
  • DoneAllowlist in the database Exact emails, case-insensitive; Operator emails always allowed; removal takes effect at once and removes the Member's Machine.
  • DoneMembers page Lists Members with status, Machine and Active Runs; only the Operator adds or removes emails.
  • DoneEnable a Project The Operator picks a GitHub repository and its base branch to enable it as a Project.
  • DoneRead-only GitHub token One read-only fine-grained token held in the environment, never in the database.
  • DoneRemove a Project The Operator removes a Project and its Tickets and Runs from the app; refused while it has Active Runs.
  • DoneAudit log Every Run, Machine, Flow, Node and allowlist action records the Member's email and time; shown on the Audit page.
  • DoneAudit See RUN-15: actions are recorded with the Member's email and time.

Deploy and operations 4

Self-hosted, durable and safe with secrets.

  • DoneSelf-hosted deploy Web, Gateway and Postgres as one Docker Compose stack behind a Cloudflare Tunnel, or on Render.
  • DoneSecrets and masking Secrets live in the environment, never the database; token patterns are masked before logs are stored or streamed; secure session cookies.
  • DoneLatency Node output reaches the browser within a few seconds.
  • DoneDurability and log retention Flows, Runs and logs survive restarts; logs are deleted after 90 days, Runs and Outputs are kept.

  • Standard Pod image (POD-14): No container image; the Agent ships as one esbuild bundle with its own Node (ADR 0007).
  • Ticket detail (TIC-4): Not built (#40 wontfix): read the issue on GitHub; the Runs and Pull requests tabs link the Runs and pull requests.
  • Dry-run (RUN-13): Removed in ADR 0009: it overlapped with the editor's Test run (FLW-3), which stays.
  • Diff and pull request link (TRK-3): Not built (#39 wontfix): read the diff on the pull request on GitHub; the Runs and Pull requests tabs link to it.
  • Artifact (TRK-5): Not built (#39 wontfix): the pull request on GitHub takes its place; the app does not write the pull request body.
  • Batch page (TRK-6): Not built (#40 wontfix): use the Runs tab filtered by state and the Pull requests tab.
