# Environment variables

Every secret lives in the environment, never in the database in the clear (NFR-1). The one exception is the app's read-only GitHub token: an Operator saves it on the Projects page and it is stored encrypted with a key derived from `SESSION_SECRET` ([ADR 0010](adr/0010-the-github-token-is-set-on-the-projects-page.md)). There is no `GITHUB_TOKEN` variable (removed in v0.6.0).

Where each set of values lives:

| Where | File or place | Template |
| --- | --- | --- |
| Local development | `.env` at the repo root (git-ignored) | [.env.example](../.env.example) |
| Production on Render | `render.yaml` and the Render dashboard | [render.yaml](../render.yaml) |
| Self-hosted Compose stack | `deploy/.env.production` (git-ignored, `chmod 600`) | [deploy/.env.production.example](../deploy/.env.production.example) |
| A Member's Machine | the Agent's environment (usually nothing to set) | — |

Values below are examples. Generate every secret with `openssl rand -base64 32` and never paste real values into docs, issues or chat.

## Web app and Gateway

| Variable | Used by | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `DATABASE_URL` | web, gateway, `db:*` scripts, `drizzle-kit` | Yes | — | Postgres connection string, e.g. `postgres://clauderon:clauderon@localhost:54329/clauderon` locally. |
| `SESSION_SECRET` | web, gateway | Yes | — | Signs Auth.js cookies and the Gateway tickets, and derives the key that encrypts the GitHub token and Run attachments. Web and Gateway must share it. Rotating it signs everyone out; an Operator then saves the GitHub token again, and attachments not yet delivered cannot be read. |
| `GOOGLE_CLIENT_ID` | web | Yes | — | Google OAuth client id. |
| `GOOGLE_CLIENT_SECRET` | web | Yes | — | Google OAuth client secret. |
| `AUTH_URL` | web, gateway | Yes outside localhost | the request's origin | Public origin of the web app, e.g. `https://clauderon.example.com`. Behind a proxy (Render) the app sees `localhost`, so install commands and pairing links are wrong without it. |
| `OPERATOR_EMAILS` | web, gateway | Yes | empty | Comma-separated emails that are always allowed and manage the allowlist, e.g. `alice@example.com,bob@example.com`. |
| `GATEWAY_URL` | web | Yes outside localhost | `ws://localhost:4000` | The Gateway's WebSocket URL as browsers and Agents reach it (`wss://…` in production). Agents learn it from `GET /api/agent-config` when they pair. |
| `GATEWAY_PORT` | gateway | No | `4000` | Port the Gateway listens on (`10000` on Render). |
| `WEB_URL` | gateway | No | `AUTH_URL` | Public web URL used in the approve links the Gateway returns to pairing Agents. |
| `AGENT_BUNDLE_DIR` | web | No | `../host-agent/dist` (relative to `apps/web`) | Folder with the built `agent.mjs` and `agent.json` that `/agent/*` serves. |
| `AGENT_HOME_NAME` | web | No | `.clauderon-dev` under `next dev`, else `.clauderon` | Folder under the Member's home that this web app's install script installs the Agent into. |
| `APP_VERSION` | web | No | unset (no version shown) | Release tag shown in the sidebar. `deploy/deploy.sh` sets it from the latest git tag. |
| `TEST_DATABASE_URL` | tests | For tests | — | Postgres server where each test file creates and drops its own database. |
| `NODE_ENV` | web | No | set by Next.js | Only changes the `AGENT_HOME_NAME` default. |

## Render (production)

`render.yaml` sets these; the ones marked `sync: false` are entered in the Render dashboard ([deployment guide](deployment.md)).

| Variable | Service | Source |
| --- | --- | --- |
| `SESSION_SECRET` | both (group `clauderon-shared`) | Generated by Render |
| `OPERATOR_EMAILS` | both (group `clauderon-shared`) | Dashboard |
| `DATABASE_URL` | both | From the `clauderon-db` database |
| `GATEWAY_PORT` | gateway | `10000` |
| `WEB_URL` | gateway | Dashboard: the web service's `https://…` URL |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | web | Dashboard |
| `AUTH_URL` | web | Dashboard: the web service's own `https://…` URL |
| `GATEWAY_URL` | web | Dashboard: the Gateway's URL with `wss://` instead of `https://` |

## Self-hosted stack (`deploy/.env.production`)

`deploy/compose.yml` turns these into the variables above.

| Variable | Required | Default | Description |
| --- | --- | --- | --- |
| `POSTGRES_PASSWORD` | Yes | — | Password of the stack's Postgres (random secret). |
| `SESSION_SECRET` | Yes | — | As above (random secret). |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Yes | — | Redirect URI `https://<WEB_HOSTNAME>/api/auth/callback/google`. |
| `WEB_HOSTNAME` | Yes | — | e.g. `clauderon.example.com`; becomes `AUTH_URL` (`https://…`) and the Gateway's `WEB_URL`. |
| `GATEWAY_HOSTNAME` | Yes | — | e.g. `clauderon-gateway.example.com`; becomes the web app's `GATEWAY_URL` (`wss://…`). |
| `CLOUDFLARE_TUNNEL_TOKEN` | Yes | — | Filled in by `deploy/deploy.sh tunnel`. |
| `OPERATOR_EMAILS` | Yes | — | As above. |
| `WEB_HOST_PORT`, `GATEWAY_HOST_PORT` | No | `3000`, `4000` | Ports on `127.0.0.1` for checks on the host. |

`deploy/backup.sh install` also reads `BACKUP_DIR` (where daily dumps go, default `deploy/backups/`), and `deploy/deploy.sh tunnel` reads `TUNNEL_NAME` (default `clauderon`).

## Agent (on a Member's Machine)

Nothing needs to be set: the installer and Pairing configure the Agent.

| Variable | Default | Description |
| --- | --- | --- |
| `CLAUDERON_HOME` | `~/.clauderon` | The Agent's directory: Pairing, link state, clones and worktrees. |
| `CLAUDERON_BASH` | `bash` on the PATH; on Windows, Git Bash where Git for Windows installs it | bash used for every command. |
| `CLAUDERON_URL` | — | Web app URL for `pair` when none is passed on the command line. |
| `GATEWAY_URL` | from Pairing | Overrides the Gateway URL the Agent got when it paired. |
| `CLAUDERON_WEB_URL` | from Pairing | Overrides the web app URL the Agent updates itself from. |
| `CLAUDERON_NO_UPDATE` | unset | Set to turn off self-updates. |
| `CLAUDERON_NO_BROWSER` | unset | Set to stop `pair` from opening the browser. |

The Agent sets other variables itself and they are not meant to be set by hand: `CLAUDERON_SERVICE` and `CLAUDERON_PATH` for the user service, and, on Node processes, `CLAUDERON_ATTEMPT_ID`, `CLAUDERON_EXPECT_COMMIT` and the `*_FILE` variables for file inputs (`CLAUDERON_SUMMARY_FILE`, `CLAUDERON_TEST_RESULT_FILE`, `CLAUDERON_RETRY_CONTEXT_FILE`).

## Adding a variable

Document it in `.env.example` (and `deploy/.env.production.example` or `render.yaml` when production needs it) and in this file, in the same pull request. Web and Gateway restart separately, so a new required variable must have a safe default or be deployed to both first.
