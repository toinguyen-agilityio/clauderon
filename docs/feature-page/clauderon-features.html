Turn GitHub issues into pull requests you can review.

Clauderon is a web app for one team. You pick the issues, an AI assistant (Claude Code) does the work on your own computer, and you come back to a pull request.

Tickets

A Ticket is an open GitHub issue that Clauderon has pulled in. A Project is one GitHub repository you turned on.

  • Turn on a GitHub repository as a Project and choose its main branch.Done
  • Pull its open issues in as Tickets with one Sync button.Done
  • See every open pull request of a Project.Done
  • A detail page for each Ticket or batch.Not built

Flows and Nodes

A Flow is the recipe. A Node is one step in it, such as “ask Claude to plan”, “run the tests” or “wait for a person to approve”.

  • Draw a Flow on a canvas from a shared library of steps.Done
  • Steps only connect when the data fits, and loops are not allowed.Done
  • Start from ready-made sample Flows, copy them, edit them, export and import them as files.Done
  • Ask Claude to draft a Flow for you.Done
  • Four kinds of step: Claude does work, a command runs, a person approves, or Claude asks questions that a person answers.Done

Runs

A Run is one Ticket going through a Flow.

  • Start several Tickets at once; each gets its own safe copy of the code.Done
  • A practice mode (Dry-run) that pretends to do every step, so you can try a Flow for free.Done
  • Retry from any step, or cancel. A failed step stops the Run; nothing loops by itself.Done
  • Live logs with secrets hidden, a count of AI usage per Run, a Pull requests page and a record of who did what.Done
  • Built-in view of the code changes inside the app.Not built

Machines

A Machine is your own computer, once you have connected it to Clauderon. A small helper program (the Agent) runs on it.

  • Connect your computer with one install command and a short code you approve in the app.Done
  • A health check (Doctor) that tells you what is missing on your computer.Done
  • The helper updates itself. Works on Mac, Linux and Windows.Done
  • Choose how many Runs your computer does at once; extra Runs wait in line.Done
  • Live CPU and memory use of your computer.Not built
  • Work in a sandbox. Today the helper has the same permissions as you, so use it with care.Not built

People in the loop

  • A “Needs you” inbox lists every Run that is waiting for a person.Done
  • Approve a plan, or reject it with feedback that the next try will read.Done
  • Answer Claude's questions in a simple form.Done
  • Any team member can answer or cancel any Run, not only the person who started it.Done

How it works

Six steps from a GitHub issue to a pull request.

  1. Pair your computerInstall the small helper with one command and approve the short code it shows. You sign in to Claude Code and GitHub on your computer once.
  2. Pick a projectTurn on a GitHub repository, then press Sync. Its open issues appear as Tickets.
  3. Pick a FlowA Flow is a recipe of steps, for example “plan, get approval, write the code, run the tests”. Copy a sample and change it if you like.
  4. StartSelect Tickets and press Start. Each one becomes a Run that goes through the steps one by one on your computer. Try a practice run first if you are unsure.
  5. Stay in the loopWhen a step needs a person, the Run waits in your “Needs you” inbox. Approve a plan, answer questions, or retry a step that failed.
  6. Review the pull requestAt the end the Run sends its work to GitHub as a pull request (a proposed change), under your own name. You and your team review it as usual.

FAQ

What does Clauderon do?

It takes GitHub issues your team picks and runs each one through a recipe of steps, using an AI assistant. The result is a pull request for people to review.

Whose computer does the work?

The computer of the person who pressed Start, using their own Claude Code and GitHub sign-ins. The web app never sees those sign-ins.

What can it change on GitHub?

The app itself can only read. Changes are made from your computer, under your name: it sends a branch and opens a pull request. Nothing is merged without a person.

Is it safe to use on real projects?

Be careful. The steps run with your own permissions and there is no sandbox yet, and a bad issue could steer the AI. Each Run works in its own copy of the code, away from your own files.

What is not built yet?

A sandbox for Runs, live CPU and memory use of a computer, a built-in view of code changes, and detail pages for each Ticket or batch. See the Features section for the full list.
